# ADR-0015 — Downloads are handed to qBittorrent; Prowlarr or qBittorrent's plugins find the releases

**Status:** accepted · 2026-10-24 · implemented

**Context.** People want to find a film or episode they do not have and get it into the library. Theama must stay a library, not a torrent client: bundling an engine, indexers or search plugins would be a large feature with its own legal and security surface. qBittorrent and Prowlarr are what the target audience already runs, and both have documented local HTTP APIs.

**Decision.**
- **qBittorrent does the downloading.** Theama talks to its Web API from the service (`apps/server/src/downloads/qbittorrent.ts`): login with the `SID` cookie and the Origin/Referer header its CSRF check requires, add a link, list, pause/resume (`stop`/`start` on 5.x, falling back to `pause`/`resume` on 4.x), remove. The UI never talks to qBittorrent: its CSP only allows the service, and the service is the one place that holds the credentials.
- **Two release sources behind one result type** (`Release`): Prowlarr's JSON search (preferred when set up) and qBittorrent's own search plugins. Theama bundles no sites, indexers or plugins. Hits are filtered to the title asked for (`release.ts`) and ranked by seeders and resolution; Theama does not rank by "best" beyond that.
- **Links never reach the UI.** A search returns opaque ids; the service remembers the magnet link or `.torrent` address for 30 minutes, and `POST /downloads` accepts only such an id. A typed-in address is never fetched, so the endpoint cannot be used to make the service request arbitrary URLs. Only `magnet:` and `http(s):` links are kept.
- **By default only our own downloads are shown or touched.** Everything Theama adds carries the qBittorrent tag `theama` (and `theama-movie` / `theama-series`). The list, pause, resume, remove and file-choice operations check the hash against that tag first, so the rest of the person's torrents are none of Theama's business. A setting, off by default (`downloadsShowAll`, the switch "Show all my qBittorrent torrents" on the Downloads page), lifts that: the list then includes every torrent (marked `own: false`, shown as "Not added by Theama") and the same operations work on them. Even then a hash must exist in qBittorrent; Theama never acts on one it cannot see. Library rescans on completion still only happen for downloads Theama added, since only those know their kind.
- **Choosing files.** `GET`/`PUT /downloads/:hash/files` list a torrent's files and set exactly which are wanted (qBittorrent's `torrents/files` and `filePrio`: priority 0 skips a file, 1 downloads it; files that are already wanted are left as they are so a raised priority survives). A magnet link has no file list until qBittorrent has fetched its details (state `metadata`), so the dialog waits and looks again; the choice is made from the list afterwards rather than at the moment of adding, because adding a magnet link paused is not a reliable way to get its details first. At least one file must stay wanted: stopping everything is "remove". Skipped files take no space, and what was already downloaded stays on disk.
- **Credentials** (qBittorrent address, user and password; Prowlarr address and API key) live as JSON in the `secrets` folder, like the TMDB key and under the same trust model (ADR-0004): never in the database, never returned by the API, redacted from the diagnostics report. A connection is tested before it is kept; a rejected login is refused, a client that is merely not running is kept and reported as unreachable.
- **Where files land.** Each kind (movies, series) can be mapped to one of the person's library folders; the download's save path is that folder. When the monitor sees a download finish it queues a scan of that folder, in addition to the folder watcher.
- **Progress** is polled by a `DownloadMonitor` (every 3 s while a window is open, 20 s otherwise) and pushed as `downloads.changed` only when it changes.

**Consequences.** Theama works fully without any of this; the Downloads page and the "Find a download" button on title pages only appear useful once a client is set up. Hit lists depend on the person's own indexers, and a Prowlarr link that qBittorrent cannot fetch (different machine, different address) fails inside qBittorrent, not in Theama. The person is responsible for what they download; the settings page says so. Not done: seeding limits, categories, per-file priorities beyond wanted / not wanted, and moving a torrent's data after the fact.
