# ADR-0013 — Resume position and automatic watched, through per-player local interfaces

**Status:** accepted · 2026-10-20 · amends ADR-0011 ("no resume, no automatic watched")

**Context.** ADR-0011 left "watched" as a manual mark because external players do not report progress uniformly. The person asked for the next episode to follow what they actually watched, and for a stopped video to resume where it stopped, but only if they watched more than five minutes.

**Decision.**
- **Which players.** VLC, mpv and MPC-HC / MPC-BE, the ones that can be watched from outside. PotPlayer, programs the person added and the system default cannot report a position: they stay as before (a start is remembered, "watched" is marked by hand). The Settings → Playback page says which players are tracked.
- **How.** The desktop shell adds a switch to the command line that makes the player listen on this PC only, then watches it; the backend never talks to a player.
  - mpv: `--input-ipc-server` on a named pipe with a random name; position arrives as `time-pos` property changes. Tracked series use `--keep-open=yes`; `eof-reached` ends an episode's viewing while the player stays available for another file.
  - VLC: `--extraintf=http` on `127.0.0.1`, a free random port and a random password (never logged), polled every 5 s. `--no-one-instance` makes each start its own VLC, otherwise a running VLC would take the file and never open our interface.
  - MPC-HC / MPC-BE: `/new /webport <port>`, polled on `/variables.html` (times in milliseconds). Each launch has its own instance and tracking port. Series use `/play /slave <window>` without `/close`. A hidden PowerShell/C# message window receives native end-of-stream notifications and sends file, subtitle and resume arguments to that particular player window through `WM_COPYDATA`. Once per loaded file it selects the runtime-only After Playback: Do Nothing command, preventing the player's folder playlist from advancing before Theama's countdown without changing the permanent preference. EOF notifications received before the first identified sample are retained until progress is available. JSON on stdin keeps media paths out of PowerShell source. The bridge source is bundled into the desktop application. Process exit ends tracking promptly; startup and near-end polling are faster so short episodes are still observed.
  - Resuming: `--start=<s>` (mpv), `--start-time=<s>` (VLC), `/start <ms>` (MPC).
  - Everything is still an argument array with `shell: false`. The shell only forwards what it read (`PUT /playback/files/:id/progress`); it never takes a path or a command from the UI.
- **Rules live on the backend** (`PlaybackRepo.recordProgress`): from 90 % of the runtime the file is marked watched (`source = 'player'`) and the position is cleared, including episodes shorter than five minutes. Unfinished playback under 5:00 is ignored (and an earlier saved position is not overwritten); otherwise the position is saved. Completion checks retain subsecond player precision; stored resume positions are whole seconds. A file that is already watched is left alone unless this viewing reaches the end again. Marking watched or unwatched by hand clears the saved position.
- **Next episode (updated 2026-10-29).** Natural EOF finalizes progress without closing the player. VLC detects a playing-to-stopped transition with a last valid sample within two seconds of its known duration; reset positions are discarded. mpv observes `eof-reached`; MPC receives native end-of-stream notifications. MPC-HC can omit that notification when its runtime Do Nothing action leaves the graph running at the exact duration, so that explicit endpoint also qualifies; a paused graph never qualifies through this fallback. Crossing the 90 % watched threshold alone never starts the countdown. After a successful final submission, the desktop offers the configured countdown in a silent bottom-left notification when automatic next episode is enabled and a playable local episode follows. Cancel or Escape stops the countdown; Play now starts immediately. The next file loads in the same player instance using fresh, validated launch information, subtitle preferences and resume position. Closing manually at or beyond 90 %, or during an existing countdown, still qualifies; continuation launches the original player type if its process has exited. The final episode has no prompt and its player stays open.
- **Continuation ownership.** The desktop owns one-use opaque offer IDs. The renderer can accept or cancel an offer, never supply a continuation path. EOF is finalized once and tracking remains connected to detect external file changes. Manual playback, a changed file or a failed tracking connection invalidates stale offers; cancellation is not undone by later process exit. Controls for a live player must confirm the new file before starting its tracker. Failed live-player controls show a playback error and never create a duplicate player. Player controls retain local-only ports, authentication and named pipes; standalone film playback remains unchanged.
- **Never the wrong file.** Empty startup filenames are ignored. The tracker compares MPC's full path where available and otherwise the filename, ending tracking when another file is loaded.
- **Failure is quiet.** Reports are serialized and final reports follow all pending saves. A failed final submission is retried twice, after one and three seconds; the next episode is offered only after a successful final response. If tracking or reporting remains unavailable, playback is unaffected.

- **Silent fullscreen notification (updated 2026-10-29).** The desktop shows the countdown in a small, muted, non-activating window at the bottom left of the player's display, above composited fullscreen video. It includes Cancel and Play now and keeps the player focused. The desktop owns the countdown; the notification has a dedicated sandboxed preload exposing only offer updates and validated actions from its own main frame. If the notification window cannot load, the existing in-app countdown remains a fallback. The existing Settings → Playback automatic-next toggle controls both autoplay and its notification, persists across restarts, and is checked again before accepting a continuation. Disabled autoplay does not show a notification or open another episode. Notification content is localized in English/Greek and contains no audio or network resources.

**Consequences.** Resume and automatic watched work for the tracked players and degrade to manual behaviour for the rest. Closing Theama while a player is open loses at most the last ~15 seconds of position. "Watched for five minutes" is measured as playback position, so skipping ahead counts. An explicit playback launch opens its own tracked player; automatic episode continuation reuses it. The integrations depend on each player's supported local interfaces; if an interface is unavailable, playback remains usable. No settings or database migration is needed.
